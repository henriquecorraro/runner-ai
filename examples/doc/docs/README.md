# Docs Index

This is an example docs index for a repository.

It is intentionally generic and contains no real system details.

## Start Here

- `architecture/system-overview.md`: high-level module boundaries and runtime flow
- `features/example-feature.md`: one feature-focused doc with behavior and maintenance notes

## What Good Human Docs Should Cover

- what the repository does
- where the main modules live
- how requests, jobs, or UI flows move through the system
- business or operational constraints that matter during maintenance

## Maintenance Rule

When implementation changes affect behavior, contracts, boundaries, or operational expectations, the corresponding human docs should be updated in the same repository.
